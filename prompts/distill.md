# 收尾 prompt

用法：有实质产出的 session 结束时运行。把下方 `BEGIN` 到 `END` 之间的正文存成各 client 能快速调用的形式（Claude Code / Cursor 的自定义命令、Codex 的自定义 prompt，或文本 snippet）。实验验证有效后，再考虑做成跨 client 的 skill。

依赖的约定（见 [architecture.md](../docs/design/architecture.md)）：

- 入口文件 `AGENTS.md` 含“主题索引”和“待归类”两个小节
- 主题文件放在 `.agents/memory/topics/<主题>.md`

# 收尾：提炼本次 session

回顾本次 session，按以下步骤执行。**在我确认之前，不要修改任何文件。**

## 1. 读取现有记忆
读入口文件 AGENTS.md（含“主题索引”和“待归类”），以及本次涉及的主题文件。

## 2. 提取候选
只保留满足以下任一条的内容：
- 新的决策（附理由）
- 新的约定或禁止事项
- 踩过的坑（现象、原因、正确做法）
- 真实可用的命令或流程
- 未完成事项（附今天日期）

排除：从文件或代码能直接看出来的；只对本次有效的临时信息；未验证的猜测（如果重要，保留并标“未验证”）。

## 3. 判断归属
- 个人层（跨项目的工作原则、偏好）→ 个人原则文件
- 项目层（整个项目都适用）→ AGENTS.md
- 主题层（只和某个主题有关）→ `.agents/memory/topics/<主题>.md`
  - 主题文件已存在：写进去。
  - 不存在、且“待归类”里没有这个主题：在“待归类”里加一行（日期、主题名、一句话内容）。
  - 不存在、但“待归类”里已有这个主题（即第二次出现）：提议新建主题文件，把“待归类”里的相关条目迁过去，并在“主题索引”加一行（主题名、一句话说明、什么时候该读）。
- 涉及其他主题的，在主题文件开头的“相关”里提议加上链接。

## 4. 检查已有记忆
列出与新内容冲突、重复或已过时的条目；“进行中”超过 14 天没更新的也列出。提议修改或删除。

## 5. 脚本与工具
- **候选**：本次用过、可能再用的临时脚本，提议追加到 `$AGENT_HOME/tools/candidates.md`（日期 · 用途 · 项目 · 关键做法）。如果候选里已有同类条目，改为提议沉淀成工具（形式、位置、维护成本）。
- **评价**：列出本次调用过的工具库工具（命令路径在 `$AGENT_HOME/tools/<id>/` 下的），提议评价 ok / partial / fail 加一句话；确认后记录。
- **清理**：候选超过 90 天没再出现的，提议删除。

## 6. 长度预算
写入后如果超出预算（入口 ~150 行、主题 ~80 行、个人原则 ~60 行），同时提议如何压缩。

## 7. 输出格式
```
## 摘要
一句话。

## 提议的修改
按文件分组，用 diff 展示，每条附一句理由。

## 脚本与工具
候选、沉淀建议、工具评价。没有就写“无”。

## 需要我确认的问题
没有就写“无”。
```

没有值得记录的内容，就直接回复“本次无需写回”，不要凑数。

## 8. 等待确认
我可以逐条接受、修改或拒绝。确认后再写入。不要自动提交 git。
