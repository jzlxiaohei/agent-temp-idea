# 设计原则

本文是本项目自身的设计原则。给 agent 用的工作原则见 [prompts/principles.md](../../prompts/principles.md)。

## 1. 领域无关

不假设项目是 monorepo，不假设有清晰的目录分层，也不假设是编码项目。核心模型只依赖“文件夹 + markdown”。编码项目可以额外享受路径规则、按目录分层等增强，但这些是可选适配，不是前提。

## 2. 不发明新格式，对齐社区

入口用 AGENTS.md（Claude Code 通过 `CLAUDE.md` 里的 `@AGENTS.md` 转接），可复用流程用 Agent Skills。本项目只做：约定结构、写 prompt、必要时用脚本抹平各 client 的差异。

## 3. 存储和基建用现成的

记忆以私有 git 仓库里的 markdown 为基线；需要语义检索、云端访问等能力时，选型接入第三方记忆服务（优先底层是纯文本、可导出的）。不自建记忆服务。

## 4. 少即是多，按需生成（硬约束）

- **不一次铺满。** 新项目只建入口文件；主题文件用到才建。
- **主题第二次出现时**才提议建主题文件。
- **只写推断不出来的东西：** 非显然的约定、做过的决策及理由、踩过的坑、禁止事项、真实可用的命令。
- **长度预算**（初步）：入口文件 ≤ ~150 行，主题文件 ≤ ~80 行，个人原则 ≤ ~60 行。超出就合并、删减或拆分。
- **生成的一律是草稿**，由人确认后才写入。

## 5. 判断交给 LLM，确定性操作交给脚本

文件同步、软链接、长度和引用检查用脚本做。只有“该写什么、写到哪”这类判断交给 LLM。

## 6. 记忆可版本化、可溯源

记忆是纯文本，推荐放在 git 里。每条重要内容尽量带日期和来源（哪次 session、什么理由）。

## 7. 成本和收益都要可衡量

先用两周实验验证（见 [experiment.md](experiment.md)），再决定是否投入工具。

## 8. 自用优先

满足自己在 Cursor / Claude Code / Codex 之间切换的需要；能拿现成的就拿现成的。
