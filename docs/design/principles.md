# 设计原则

## 1. 不发明新格式，对齐社区

指令文件用 AGENTS.md，可复用流程用 Agent Skills（SKILL.md）。本项目只做三件事：约定目录结构、提供 skills、用脚本抹平各 client 的差异。

## 2. 少即是多，按需生成（硬约束）

上下文不是越多越好：冗长或自动生成的 context 文件会增加 token 成本、引入噪音，效果可能反而变差。因此：

- **不一次铺满。** init / adopt 只生成根目录的 AGENTS.md，外加最多 1–2 个最常改的包。
- **用到才建。** 子目录的 AGENTS.md、`docs/topics/*.md` 只在真实需要时才创建：
  - 某个包第一次有 session 产出值得沉淀的结论时，才由 `session-distill` 提议创建该包的 AGENTS.md；
  - 一个横切主题**第二次**出现时，才提议建 topic 文件。
- **只写推断不出来的东西：** 非显然的约定、踩过的坑、禁止事项、真实可用的命令。不写“本项目使用 React”这类 agent 读代码就知道的内容。
- **硬性长度预算**，由 lint 强制执行（具体数值在 spec 中定，初步设想：根文件 ≤ ~150 行，子目录文件 ≤ ~60 行）。
- **生成的一律是草稿**，以 diff / PR 形式提交，由人删减确认后才落盘。

## 3. 判断交给 skill，确定性操作交给脚本

软链接、文件生成、长度和引用检查用脚本做：快、稳定、不耗 token。只有“该写什么、写到哪”这类判断才交给 LLM。

## 4. 记忆进 git

所有记忆变更都和代码一起走 git：可审阅、可追溯、可回滚。

## 5. 落地成本和收益都要可衡量

- 成本目标：新仓库 10 分钟内完成 init；已有仓库首次 adopt 1 小时内完成（含人工审阅）。
- 收益验证：从真实任务里挑 5–10 个，比较有无规范时的返工次数、重复交代背景的次数、犯同类错误的次数。

## 6. 自用优先

先满足自己在 Cursor / Claude Code / Codex 之间切换的需要；能拿现成的就拿现成的，或以它为基准改造。
