# 如何调用大模型

## 结论

**核心流程本身不直接调用大模型。** 日常在 Cursor / Claude Code / Codex 里工作，模型由 client 自己调用；原则 prompt、收尾 prompt 都在 session 里执行。`tools/bin/` 下的统计脚本是确定性代码，也不调用模型。

只有出现“不在交互 session 里、又需要模型参与”的场景时，才需要本项目自己去调用。下面是三条路径，按场景选，不是三选一。

## 三条路径

| 场景 | 方式 | 状态 |
|---|---|---|
| 交互工作 | client 自带的模型调用 | 主路径，现在就用 |
| 自动化任务 | headless agent CLI | 以后，有需求时再做 |
| 工具内部的小调用 | 直接调 API，多厂商时经网关 | 按需 |

### 1. 交互工作（主路径）

- 在 client 里工作，什么都不用做。
- 想换模型，在 client 里切换；需要统一管理多个 agent CLI 的模型、provider、多账号时，可以加 Magpie（见下文“模型接入层”）。

### 2. 自动化任务：headless agent CLI

适用场景（目前都还没有，列出来备用）：

- 定时整理记忆：合并重复、清理过期、检查冲突
- 批量收尾：对一段时间内的 session 记录统一跑收尾流程
- 跨 agent 对比实验：同一个任务交给不同 agent，比较结果

方式：调用各家的非交互模式，例如 `claude -p`（Claude Code）、`codex exec`（Codex）、`cursor-agent`（Cursor CLI，⚠️ 命令和参数待核实）。

为什么选它而不是直接调 API：

- agent CLI 会自动读 AGENTS.md、个人原则、skill，能读写文件、调用工具。用 API 的话，这些都要自己重做一遍。
- 沿用已有的登录和配置，不需要另外管理。

做法：写一个适配脚本（暂名 `tools/bin/agent`），统一接收“任务 + 工作目录”，内部选用某一家 CLI 执行，输出统一格式。这和“一份配置 → 适配各家”的思路一致，不绑死某一家。

注意：

- 各家 CLI 的参数、输出格式、权限控制都不同，适配脚本要处理这些差异。
- 订阅账号用于自动化任务，是否符合各家的使用条款，需要核实（⚠️）。
- 自动化任务里的写入同样要遵守“提议 → 确认”。可以先生成提议文件，人工确认后再应用。

### 3. 工具内部的小调用：API / 网关

适用场景：某个工具的脚本需要一次纯文本进出的模型调用，例如摘要、分类、抽取。不需要读文件、不需要调用工具。

方式：

- 只用一家：直接用该厂商的 SDK 或 API。
- 需要多家或想随时切换：经网关统一接口，如 LiteLLM（可自建）、OpenRouter（托管服务）。
- 密钥放在环境变量或密钥管理里，不写进仓库。

要求：

- 这类调用计入工具统计：除了调用记录，再记模型名和 token 用量（以后实现）。
- 先问能不能不用模型：能用确定性代码解决的，不调模型。

## 模型接入层（可选）

| 工具 | 管什么 | 和本项目的关系 |
|---|---|---|
| Magpie | 给 Claude Code、Codex 等 agent CLI 统一选模型、切 provider、多账号切换、路由 | 位于 client 之下。需要切换模型或 provider 时再接入，不影响本项目的结构 |
| LiteLLM / OpenRouter | 给 API 调用提供统一接口 | 只服务路径 3 |

## 选择顺序

1. 能用确定性代码解决的，不调模型。
2. 交互工作中能做的，就在 client 里做。
3. 需要自动化、且需要读文件或用工具的，用 headless agent CLI。
4. 只需要一次纯文本调用的，用 API。
